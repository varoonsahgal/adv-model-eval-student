Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

RAG (retrieval-augmented generation)
Look up relevant text first, then have the LLM answer from it
Token
The sub-word unit LLMs read and bill by; ≈ ¾ of an English word, ≈ 4 characters
Chunk
One indexed piece of a document: the unit you embed, retrieve and send
Overlap
Text repeated at the end of one chunk and the start of the next, so boundary sentences appear whole
Fixed / recursive / semantic chunking
Cut every N tokens / cut at the coarsest natural break that fits / cut at section headings
Embedding
A list of numbers (384 here) a model assigns to a text; similar meanings point in similar directions
Cosine similarity
How closely two embeddings point the same way (1 = same, 0 = unrelated). Topical closeness, not "answers the question"
Dense retrieval
Rank chunks by cosine similarity to the question's embedding
BM25 (sparse retrieval)
Classic keyword scoring: shared words count, rare words count more, long chunks count less
Hybrid search
Run dense and BM25, then merge the two rankings
RRF (Reciprocal Rank Fusion)
The merge rule: score = Σ 1 / (60 + rank). Uses ranks only, so score scales never matter
Top-K / K
How many chunks you keep and pass to the generator
All 34 terms in this lab
Reranker
A slower model that re-scores ~20 candidates and keeps the best K
Bi-encoder vs cross-encoder
Embed question and chunk separately and compare (fast) vs read them together in one model (slower, sharper)
MaxSim
This lab's offline reranker: score a chunk by its single best-matching sentence
Context headers / Contextual Retrieval
Index each chunk with "doc title > section" (free) / with an LLM-written summary (Anthropic, 2024)
Distractor
A doc that shares a question's vocabulary without being its best answer (here: the 1.x guide, the FAQ)
Relevant document
A document that contains the answer (relevant_doc_ids)
Evidence span
The exact characters that answer a question (evidence)
Recall@K
Share of relevant documents touched by the top-K chunks
Precision@K
Share of the top-K chunks that come from a relevant document
nDCG@K
Rank-weighted hit score: relevant chunks count more near the top (1.0 = ideal order)
MRR
Mean of 1 / rank of the first relevant chunk
Answer found / retrieval failure rate
1 if ≥ 50% of the evidence characters were retrieved / 1 − answer found
IoU (intersection over union)
Evidence ∩ sent ÷ evidence ∪ sent: punishes missing the answer and padding around it
Vector database / embedded mode
A store that answers nearest-neighbour queries / one running inside your Python process
Adapter
A thin interface (recreate, insert, count, search) so backends can be swapped
Mock provider
An offline stand-in generator; here it copies two context sentences, so it can't invent text
Responses API
OpenAI's current API for new projects (client.responses.create)
Faithfulness / answer relevancy
Is every answer claim in the context? / does the answer address the question? (word-overlap proxies here)
Abstention / over-refusal
Declining to answer / declining although the evidence was retrieved
Parametric knowledge
What an LLM memorized in training, as opposed to what you retrieved for it
Context rot
Quality loss as the prompt grows and fills with look-alike distractors
Paired test (McNemar)
Compare two systems on the same questions using only the ones they disagree on
