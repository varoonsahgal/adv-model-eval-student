Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

Agent / agent loop
An LLM that repeatedly picks a tool, reads the tool's result, and picks again until it answers
Tool call / tool output
A function the model asks the harness to run (e.g. issue_refund) / the text that comes back, which the model reads
System prompt
The developer's standing instructions to the model (GOOD_PROMPT)
Direct prompt injection
Attack text the user types into the chat
Indirect prompt injection
Attack text hidden in data the agent reads (a memo, profile, email, web page)
Attack surface
Every place untrusted text can enter the agent
Invoice memo (description)
The free-text line on an invoice; here third-party marketplace apps write it
Escalation
Handing a case to a human specialist (escalate_to_human); required for refunds over $500
Trial, K
One independent run of a task with a fresh database; K = 5 trials per task
State / policy / response grader
Lab 06b's checks on the final database, on the rules along the way, and on the final message
Attacker goal (state-based)
The attacker's win condition, checked in the database ("INV-1001 got refunded"), not in what the model said
Benign utility
Share of normal (no-attack) trials that pass
All 30 terms in this lab
Utility under attack
Share of attacked trials where the customer's request still passes
ASR (attack success rate)
Share of attacked trials where the attacker's goal was met
AgentDojo
A 2024 research benchmark (NeurIPS) that pairs agent tasks with injection attacks; source of the three metrics
OWASP, ASI01–ASI10, LLM01
A nonprofit that publishes security top-10 lists; ASI = its Agentic list (Dec 2025); LLM01 = Prompt Injection on its LLM list
Lethal trifecta
Private data + untrusted content + a way to act or communicate externally; remove one and attacks get much harder
Spotlighting
Marking untrusted text so the model can tell it's data: delimiting, datamarking, or encoding
Guardrail / tool-call guard
Code that inspects a tool call before it runs and can block it
Evaluator
A check that scores behavior after the fact; it can't block anything
False positive / miss
The guard blocks a legitimate call / lets an attacker's call through
Defense in depth
Stacking independent defenses so one layer's miss is another's catch
Utility tax
The benign utility a defense costs compared with no defense
CaMeL
A 2025 Google DeepMind design that lets only the trusted request decide which actions run
Confidence interval / Wilson upper bound
A range of true rates consistent with your data / its top end, computed so it stays sensible at small n and zero successes
Rule of three
Shortcut: 0 events in n trials → 95% upper bound ≈ 3/n
pass@k / pass^k
Chance that at least one of k tries succeeds / that all k succeed
Attack campaign / adaptive attack
Many attempts per attack / an attacker who rewrites the attack using feedback, not just retries
Design patterns (Plan-Then-Execute, Dual LLM, …)
Agent architectures in which untrusted text can't choose consequential actions, e.g. fix the action plan from the user's request before reading any data
Exfiltration
Sneaking data out to an attacker (e.g. emailing another customer's invoices)
