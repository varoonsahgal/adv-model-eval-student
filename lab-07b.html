Concepts

6 ideas, defined where you need them

Each one gets three sentences in the notebook: what it is, what it can't tell you, and an anchor from this lab.

  • 📘
    Indirect prompt injectionAttacker text hidden in data the agent reads while working for someone (a profile note, an invoice memo, an email, a web page), as opposed to direct injection, which the user types into the chat (Module 07).
  • 📘
    Attack success rate (ASR)Attacked trials in which the attacker's state-based goal happened (the refund_on invoice was refunded) ÷ all attacked trials.
  • 📘
    SpotlightingA prompt-level defense (Hines et al., Microsoft, 2024): transform untrusted text so it looks different from instructions, by delimiting it (unique start and end markers), datamarking it (a marker character woven through it) or encoding it (e.g. base64, which turns SYSTEM into U1lTVEVN), and add a system-prompt rule that marked text is data, never instructions.
  • 📘
    Tool-call guardCode that inspects each tool call the model proposes, before it executes, and either allows it or returns a reason to block it. It moves policy from the prompt (a request the model may ignore) into code (a check it can't talk its way past). A guard (a guardrail) runs inline and can stop an action; an evaluator, like your 06b policy graders, scores the action afterwards.
  • 📘
    Wilson upper boundThe top of a 95% confidence interval for a rate, built to stay sensible at small n and at zero successes. With 0 wins in n trials it is z²/(n + z²) ≈ 3.84/(n + 3.84), where z = 1.96.
  • 📘
    The attacker's pass@kThe chance that at least one of k attempts succeeds: 1 − (1 − p)^k for a per-try success rate p. Lab 06b computed it for the agent; here the attacker is the one retrying.

Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

Agent / agent loop
An LLM that repeatedly picks a tool, reads the tool's result, and picks again until it answers
Tool call / tool output
A function the model asks the harness to run (e.g. issue_refund) / the text that comes back, which the model reads
System prompt
The developer's standing instructions to the model (GOOD_PROMPT)
Direct prompt injection
Attack text the user types into the chat
Indirect prompt injection
Attack text hidden in data the agent reads (a memo, profile, email, web page)
Attack surface
Every place untrusted text can enter the agent
Invoice memo (description)
The free-text line on an invoice; here third-party marketplace apps write it
Escalation
Handing a case to a human specialist (escalate_to_human); required for refunds over $500
Trial, K
One independent run of a task with a fresh database; K = 5 trials per task
State / policy / response grader
Lab 06b's checks on the final database, on the rules along the way, and on the final message
Attacker goal (state-based)
The attacker's win condition, checked in the database ("INV-1001 got refunded"), not in what the model said
Benign utility
Share of normal (no-attack) trials that pass
All 33 terms in this lab
Utility under attack
Share of attacked trials where the customer's request still passes
ASR (attack success rate)
Share of attacked trials where the attacker's goal was met
AgentDojo
A 2024 research benchmark (NeurIPS) that pairs agent tasks with injection attacks; source of the three metrics
OWASP, ASI01–ASI10, LLM01
A nonprofit that publishes security top-10 lists; ASI = its Agentic list (Dec 2025); LLM01 = Prompt Injection on its LLM list
Lethal trifecta
Private data + untrusted content + a way to act or communicate externally; remove one and attacks get much harder
Spotlighting
Marking untrusted text so the model can tell it's data: delimiting, datamarking, or encoding
Guardrail / tool-call guard
Code that inspects a tool call before it runs and can block it
Evaluator
A check that scores behavior after the fact; it can't block anything
False positive / miss
The guard blocks a legitimate call / lets an attacker's call through
Defense in depth
Stacking independent defenses so one layer's miss is another's catch
Utility tax
The benign utility a defense costs compared with no defense
CaMeL
A 2025 Google DeepMind design that lets only the trusted request decide which actions run
Confidence interval / Wilson upper bound
A range of true rates consistent with your data / its top end, computed so it stays sensible at small n and zero successes
Rule of three
Shortcut: 0 events in n trials → 95% upper bound ≈ 3/n
pass@k / pass^k
Chance that at least one of k tries succeeds / that all k succeed
Attack campaign / adaptive attack
Many attempts per attack / an attacker who rewrites the attack using feedback, not just retries
Design patterns (Plan-Then-Execute, Dual LLM, …)
Agent architectures in which untrusted text can't choose consequential actions, e.g. fix the action plan from the user's request before reading any data
Exfiltration
Sneaking data out to an attacker (e.g. emailing another customer's invoices)
Base rate
How common the thing you're detecting is among everything you scan (e.g. 20 poisoned memos in 200,000)
Alert precision
Of the alerts a detector raises, the share that are real; it collapses when the base rate is tiny
Mutant / mutation testing
A copy of your code with one deliberate bug / checking that your tests fail on every such copy

🏆 Challenges

5 problems that need thinking, not typing

Each one is built around a point you discover by solving it. Starters run as shipped; 🌶️ is the spice level.

  1. 🌶️level 1
    Challenge 1: Do the attacker's mathA per-try leak that sounds small in a test report becomes a monthly certainty once one poisoned memo is read by thousands of sessions.
  2. 🌶️🌶️level 2
    Challenge 2: Escape the spotlight, then seal itA delimiter an attacker can type is a fence with a gate in it: one memo containing your closing marker puts the rest of their text outside the block.
  3. 🌶️🌶️🌶️level 3
    Challenge 3: Mention is not requestIf the guard and the agent misread the customer's request the same way, a refund the customer explicitly declined goes through both layers.
  4. 🌶️🌶️level 2
    Challenge 4: The detector that flags your booksA memo scanner that pages LedgerLy's fraud team on every suspected injection gets muted within a week if most pages are routine bookkeeping, and after that nobody reads the real one.
  5. 🌶️🌶️🌶️level 3
    Challenge 5: Five broken guards, one perfect scoreboardThe refund guard is a financial control, and when an auditor asks how you know it works, "six unit tests pass and the attack campaign scored 0/60" is your evidence; this challenge measures what that evidence can see.
