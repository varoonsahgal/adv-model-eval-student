Concepts

6 ideas, defined where you need them

Each one gets three sentences in the notebook: what it is, what it can't tell you, and an anchor from this lab.

  • 📘
    Recall@K (here, a hit rate)Of the documents that should be retrieved, the fraction that appear in the top K. Only the 5 returned docs were labelled here, so "all relevant" means "relevant among those 5": Recall@5 is 1 if any came back and 0 if none did, and its mean over queries is the hit rate.
  • 📘
    Faithfulness (also grounding, groundedness)Every claim in the answer is supported by the retrieved context. This task says "grounding"; from Task 6 on the lab says faithfulness; they mean the same thing.
  • 📘
    NLI entailmentA natural language inference (NLI) model reads a premise (here, the relevant docs) and a hypothesis (the answer) and returns three probabilities: entailment (the premise supports it), contradiction, and neutral (neither). Faithfulness = P(entailment). This lab's model is a cross-encoder: it reads both texts in one pass, which is more accurate than comparing two separate embeddings (one vector per text).
  • 📘
    Doc-derived (synthetic) test setQuestions written by someone reading the documents, so they borrow the documents' words. Cheap and fast, and the usual first eval set; the offline set here is one.
  • 📘
    Context sufficiencyThe retrieved text contains every fact a correct answer needs. Offline you label it from key facts (the facts an annotator says a correct answer must contain); at serving time an LLM autorater estimates it.
  • 📘
    Coverage and selective accuracyFor a system that can decline, two numbers reported together. Coverage = share of questions answered; selective accuracy = share of answered questions that are correct.

Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

RAG (retrieval-augmented generation)
Look up passages first, then have an LLM write the answer from them
Retriever / generator
The search step that picks passages / the LLM that writes from them
Chunk (here: doc)
A passage cut from a document and stored for search; each doc here is one short policy
Corpus / index
Every document you could retrieve / the searchable store built from it
Top-K
The K highest-scoring chunks handed to the LLM (K = 5 here)
Relevance label
A person's 1/0 call: is this doc on-topic for the question? On-topic ≠ contains the answer
Recall@K / hit rate
Share of the relevant docs that made the top K / share of queries with at least one
Precision@K
Share of the top K that are relevant (how much noise came along)
nDCG@K
A 0–1 ranking score that gives more credit for relevant docs near the top
MRR (mean reciprocal rank)
Average of 1 ÷ (rank of the first relevant doc)
Grounding / faithfulness
Every claim in the answer is supported by the retrieved docs (not "is true")
Distortion / fabrication / hallucination
A changed fact / a claim with no source at all / the umbrella term for confident unsupported output
All 35 terms in this lab
Stop words
Very common words a word-counting scorer throws away before comparing texts
Claim / claim-level scoring
One checkable statement in an answer (here, one sentence) / scoring each claim on its own, then keeping the weakest
NLI (natural language inference)
A model that reads a premise and a hypothesis and says entailment (supports), contradiction or neutral
Cross-encoder vs. embedding
Reads both texts together in one pass / turns each text into a vector separately and compares the vectors
Logits / softmax
A model's raw scores / the step that turns them into probabilities summing to 1
Miss rate / false-alarm rate
Bad answers a scorer passes / good answers it flags
TPR / TNR
True-positive rate (1 − miss rate) / true-negative rate (1 − false-alarm rate)
Trace / span
The record of one request through the pipeline / one step inside it
OpenTelemetry (OTel)
The open standard for recording traces; its GenAI conventions name LLM spans
Root cause
The earliest pipeline stage that went wrong
Ground truth / correctness
The trusted right answer (here: the current handbook) / whether the answer matches it
SME
Subject-matter expert; here a benefits specialist who grades answers
Doc-derived (synthetic) set vs. production sample
Questions written while reading the docs / questions real users typed
95% CI / Wilson interval
The range of true rates consistent with your score / a CI formula that behaves at small n
Index hygiene / freshness metadata
Removing outdated versions from search / tagging each chunk with its effective date
Abstention / over-refusal
Declining to answer / declining when the answer was in the docs
Context sufficiency / key facts
Whether the retrieved text contains everything needed to answer / the facts an answer must include
Coverage / selective accuracy
Share of questions answered / share of answered questions that are correct
Autorater (LLM judge)
An LLM prompted to grade something, here sufficiency
Stress test / probe
A question written to make the system fail in a specific way
CI pipeline (continuous integration)
The automated tests that run on every change; not the confidence interval
PTO · stipend · per diem
Paid time off · a fixed allowance for a purpose · a fixed daily travel allowance
401(k) · match · vesting · stock options
US workplace retirement account · employer money added when you contribute · employer money becoming yours over time · the right to buy shares at a set price, which vest, can be exercised (bought), or are forfeited

🏆 Challenges

5 problems that need thinking, not typing

Each one is built around a point you discover by solving it. Starters run as shipped; 🌶️ is the spice level.

  1. 🌶️level 1
    Challenge 1: Break the number check, then fix itA number check that accepts any number found in any retrieved text certifies a wrong reimbursement limit whenever an off-topic doc happens to mention it.
  2. 🌶️🌶️level 2
    Challenge 2: Design a stale-version detectorTwo versions of one policy in the index is the normal state of every handbook mid-update, and the retriever has no reason to prefer the new one.
  3. 🌶️🌶️🌶️level 3
    Challenge 3: Make the call on a sufficiency gate"only refuse when the context is insufficient" sounds free, but at a 10% base rate more than half of a good autorater's refusals can land on questions it should have answered.
  4. 🌶️🌶️level 2
    Challenge 4: Right digits, wrong unitA payroll help assistant tells a manager that overtime starts after 40 hours a day; the handbook says a workweek.
  5. 🌶️🌶️🌶️level 3
    Challenge 5: Score claims, not answersAnswer-level NLI flagged 3 of 9 faithful answers in Task 6, so half of its flags on the offline set were false alarms; wire it to an alert and the on-call engineer learns to ignore it before the week it fires on a real one.
