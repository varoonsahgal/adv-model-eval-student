Concepts

6 ideas, defined where you need them

Each one gets three sentences in the notebook: what it is, what it can't tell you, and an anchor from this lab.

  • 📘
    Constrained decoding (strict structured outputs)At every token the API masks what the schema forbids, so the output is valid JSON of the right shape by construction.
  • 📘
    Field accuracy vs record accuracyField accuracy counts correct (invoice, field) slots over all slots; record accuracy counts invoices with every field right.
  • 📘
    Hallucination vs omissionOn a field the source leaves empty, a returned value is a hallucination; on a field the source prints, a returned null is an omission.
  • 📘
    Label errorA gold value that the source document itself contradicts; the model is right and the answer key is wrong.
  • 📘
    Business rule (cross-field consistency)A relationship that holds on every valid invoice (line totals sum to the subtotal; subtotal + tax = total; due date ≥ issue date), checked on the output alone.
  • 📘
    Invariance testRender the same invoice in a harmless new format (day-first dates, no thousands separators, upper-case vendor) and assert the extraction does not change.

Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

Token
A word-piece. Models write text one token at a time
Structured outputs / strict mode
A provider feature that forces the response to match a schema you supply
Constrained decoding
How strict mode works: before each token, every choice that would break the schema is masked out
JSON Schema
A standard JSON document declaring which keys, types and values a record may have
Pydantic model
A Python class that declares typed fields, validates data, and exports a JSON Schema
Nullable vs optional
Nullable: the key is always there, its value may be null. Optional: the key may be missing. Strict mode wants every key, so absence is null
Gold labels (answer key)
Human-written correct values for each invoice
Comparator
The function that decides whether a predicted value equals the gold value
Normalisation
Rewriting both values to one canonical form before comparing (lowercase, no punctuation, no "LLC")
Field / record / critical-record accuracy
Share of (invoice, field) slots right / share of invoices with every field right / every critical field right
95% confidence interval (CI); Wilson interval
The range of true rates consistent with what you measured; Wilson's formula stays honest at small n
OCR
Optical character recognition: turning a scan into text. Source of l-for-I and O-for-0 typos
All 26 terms in this lab
Hallucination / abstention / omission
A value invented for an empty field / a correct null / a printed value returned as null
Payment terms
When the bill is due. Net 30: 30 days after the invoice date. Due on receipt: immediately
Purchase order (PO)
The buyer's approved order, with its own number
Three-way match
Accounts-payable control: pay only if invoice, PO and goods receipt agree
Label error
The answer key is wrong, not the model
Locale
A country's conventions for dates and numbers: 04/03 is 4 March in London, April 3 in Austin
Business rule (validator)
A relationship every valid invoice obeys (total = subtotal + tax), checked in code on every output
Vendor master
The company's reference list of approved vendors (name, country, currency, bank details)
Invariance (metamorphic) test; perturbation
Re-render the same invoice in another format (the perturbation); the extraction must not change
CI (continuous integration)
The automated tests that run on every code change. Not the confidence interval
Release gate
A pass/fail threshold; a release ships only if every gate passes
Accounts payable (AP)
The team and system that pay vendor invoices
General ledger
The company's master record of every transaction; invoices are "posted" to it
Mock provider
Recorded model outputs replayed offline, so everyone gets the same numbers
