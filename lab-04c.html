Concepts

6 ideas, defined where you need them

Each one gets three sentences in the notebook: what it is, what it can't tell you, and an anchor from this lab.

  • 📘
    Exact match (EM)Pass if the predicted SQL text equals the gold SQL text after lower-casing and collapsing whitespace. Cheap; needs no database.
  • 📘
    Execution accuracy (EX)Run the predicted and the gold query on a database and compare the result sets with a comparator, the function that decides what "equal" means. EX is the standard metric of text-to-SQL benchmarks (Spider, BIRD, BookSQL).
  • 📘
    Test-suite accuracyRun the predicted and the gold query on a suite of databases and pass only if they match on every one (Zhong, Yu & Klein, 2020). Each database comes from a fuzzer, code that copies the books and injects one kind of edge case. This suite: the demo DB, 7 fuzzed copies, and a "kitchen sink" copy with all of them.
  • 📘
    Answer-key auditRe-check every gold answer against a source of truth that doesn't share its mistakes. Here that is the report engine: the product's existing vendor, account and receivables reports, which accountants already reconcile against bank statements. report_engine(qid, db) returns the trusted number for a golden question on any database.
  • 📘
    Reading setEvery interpretation (reading) of an ambiguous question that a careful bookkeeper would accept, each with its own SQL. An answer passes if its number matches any reading.
  • 📘
    Metamorphic relationA rule connecting several answers, so that a violation proves at least one of them is wrong, with no gold. "Spend on Packaging in Q2 = April + May + June" is one. Ask the related questions, check the rule; it runs on live traffic.

Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

Text-to-SQL / NL2SQL
A model writes a SQL query from a natural-language question; the database computes the answer
Golden set
A fixed list of test questions with agreed answers, used to score every version
Gold SQL / answer key
The reference query for a golden question. Its result is treated as the right answer
Exact match (EM)
Pass if the predicted SQL text equals the gold SQL text (after trimming spaces and case)
Execution accuracy (EX)
Pass if the predicted query's result equals the gold query's result on one database
Result set
The rows a query returns, e.g. [(4200.0,)] (one row, one column)
Comparator
The function that decides whether two result sets count as "the same answer"
CTE
A WITH name AS (...) block: a named sub-query, a style choice that changes the text but not the result
Test-suite accuracy
Pass only if the results match on every database in a suite of varied databases (Zhong et al., 2020)
Fuzzer
Code that copies a database and injects one kind of edge case (voided entries, month-end timestamps…)
Lucky pass
A wrong query that matches the gold on the test database because the data that would expose it isn't there
Annotation error
A mistake in the answer key itself
All 24 terms in this lab
Report engine
The product's existing, audited report code (P&L, vendor spend). In this lab it's the trusted source for "the right number"
Reading (interpretation)
One valid way to understand an ambiguous question
Metric glossary (semantic layer)
Written definitions of business terms ("spend = bills + expenses − credits, posted only") that the model must follow
Metamorphic test
Check a relation between answers instead of each answer: Q3 total must equal July + Aug + Sep. Needs no gold
Discordant pair
A question one model got right and the other got wrong. Only these say anything about which is better
McNemar test / Wilson CI
A paired significance test on discordant pairs / a confidence interval for a pass rate (both from Lab 05b)
Bill vs bill payment
A bill records what you owe a vendor; a bill payment records paying it. Counting both double-counts
Void / draft
A voided entry was cancelled; a draft was never approved. Neither counts in any total
Vendor credit / refund
Money a vendor gives back (a credit) or you give a customer back (a refund). It reduces spend or revenue
1099 contractor
A self-employed person you pay for services; US businesses report payments to them on Form 1099-NEC
Accrual vs cash basis
Accrual counts an expense when the bill arrives; cash counts it when you pay
Fiscal vs calendar quarter
A company's fiscal year can start in any month (Harbor & Pine's starts 1 Feb), so "Q2" can mean two different date ranges

🏆 Challenges

5 problems that need thinking, not typing

Each one is built around a point you discover by solving it. Starters run as shipped; 🌶️ is the spice level.

  1. 🌶️level 1
    Challenge 1: Distill the suiteEvery database in the suite multiplies CI time on every model and prompt change, and a suite too slow to run on every change gets skipped.
  2. 🌶️🌶️level 2
    Challenge 2: Break the metric, then fix the suiteA team that reads 100% test-suite accuracy as "correct" ships the one query whose trigger isn't in any of its databases.
  3. 🌶️🌶️🌶️level 3
    Challenge 3: How wrong is production, with no gold?The launch review will ask how often Ledgerly Ask is wrong in production, and there are no labels to answer with.
  4. 🌶️🌶️level 2
    Challenge 4: One afternoon before the gateThe gate meeting is Friday and there's time to fix one thing in the eval.
  5. 🌶️🌶️🌶️level 3
    Challenge 5: Catch the habit with no goldTask 6's monitor passed a model that was wrong on 96 of 96 answers.
