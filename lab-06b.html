Concepts

6 ideas, defined where you need them

Each one gets three sentences in the notebook: what it is, what it can't tell you, and an anchor from this lab.

  • 📘
    Tool specThe three things the model sees about a tool: its name, a description, and a JSON Schema for its arguments (names, types, which are required). From those alone it decides whether to call the tool and what to pass, so a description is a prompt.
  • 📘
    Policy invariantA rule every acceptable path must obey, checked over the whole trace ("no issue_refund before a successful verify_identity for that invoice's owner"). It constrains order and arguments without prescribing one tool sequence.
  • 📘
    Do-nothing baselineThe score your graders give an agent that makes no tool calls and replies "Sorry, I can't help with that right now." (Lab 06's no-op agent).
  • 📘
    pass@k vs pass^kFrom a per-trial success rate p, pass@k = 1 − (1 − p)^k is the chance that at least one of k trials succeeds and pass^k = p^k the chance that all k do (Lab 06). Compute both per task, then average.
  • 📘
    Cost per successTotal cost of all trials ÷ number of trials that passed, ≈ cost per trial ÷ pass@1. At $0.01 a trial with half the trials failing, each good outcome costs $0.02.
  • 📘
    Paired comparisonBoth versions run on the same tasks with the same trial seeds and are compared task by task, so each difference comes from the change, not from the dice.

Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

Agent
A model run in a loop that can call tools (functions) and act on their results, instead of answering once
Tool / tool calling
A function the model may ask your code to run (also called function calling). The model only requests the call; your loop executes it
Tool spec
What the model sees about a tool: name, description, and a JSON Schema for its arguments
JSON Schema
A standard JSON format for describing data: field names, types, which are required
strict: true
Asks the API to guarantee the model's tool arguments match the schema exactly
System prompt
The standing instructions sent with every model call (PROMPT_V1, PROMPT_V2)
Agent loop / ReAct
Ask model → run the tools it requested → feed results back → repeat until it answers in text. ReAct = reason, act, observe
Token
The unit models read and bill by, roughly ¾ of an English word (the mock estimates characters ÷ 4)
Trace / span
A trace is everything one run did, in order; each model call or tool call inside it is a span
OpenTelemetry (OTel)
The open standard most tracing tools use for spans; its GenAI conventions name agent spans (chat, execute_tool)
Responses API / Messages API
The current request formats for OpenAI and Anthropic models; the adapters translate the lab's messages into them
stop_reason
Why the model stopped generating: finished, hit a limit, wants a tool, or refused
All 32 terms in this lab
Mock / seed
MockLLM is an offline fake model. A seed fixes its random choices so everyone sees the same numbers
Task
One test case: a customer request plus what success looks like
Trial
One run of one task. Each task gets several trials because agents are random
Grader
Code (or a judge model) that scores a trial
Outcome / end state
What is true in the database after the trial (refunds issued, tickets opened)
Policy invariant
A rule every path must obey, whatever the outcome ("no refund before identity is verified")
LLM judge
A model asked to grade another model's output, here for honesty against the action log
Do-nothing baseline
The score of an agent that takes no actions. A sound eval gives it ≈ 0%
Reward hacking
Scoring well by exploiting the grader instead of doing the task
Lucky pass
Right final state, but a policy was broken on the way
pass@k
Chance that at least one of k trials succeeds. Rises with k
pass^k
Chance that all k trials succeed. Falls with k. The reliability number for customer-facing agents
Wilson interval
A 95% confidence interval for a pass rate: the range of true rates consistent with what you observed
p50 / p95 latency
The time 50% / 95% of trials finish within. p95 is what your slowest 1-in-20 customers feel
Cost per success
Total spend ÷ number of passing trials. Failed trials cost money too
Capability vs regression eval
A capability eval is a hill to climb (low pass rate); a regression eval guards what already works (≈ 100%)
Paired comparison / hard gate
Paired: v1 and v2 on the same tasks and seeds, compared task by task. Hard gate: one check that blocks release on its own
CI
Continuous integration: tests that run automatically on every code change
Escalation
Handing a case to a human specialist (escalate_to_human); here required above the $500 limit
Account takeover / chargeback
Takeover: a fraudster acting as a real customer. Chargeback: a customer disputing a charge through their bank, which costs the merchant the money plus a fee

🏆 Challenges

5 problems that need thinking, not typing

Each one is built around a point you discover by solving it. Starters run as shipped; 🌶️ is the spice level.

  1. 🌶️level 1
    Challenge 1: Fool the honesty layerAn honesty judge that misses one phrasing ships every lie told in that phrasing, and customers promised money that never arrives file chargebacks.
  2. 🌶️🌶️level 2
    Challenge 2: When does "5 out of 5" mean anything?A task promoted on 5/5 becomes the evidence that a money-moving path is safe; if 5/5 can't tell 95% from 100%, the regression suite certifies 1 bad ticket in 20.
  3. 🌶️🌶️🌶️level 3
    Challenge 3: A grader that works on live trafficLive tickets carry no expect block, so a grader that needs one goes silent exactly where the money moves.
  4. 🌶️🌶️level 2
    Challenge 4: The step cap that fails your biggest customerA payment-processor glitch double-charges Maya every month for a year, and she asks for all twelve duplicates back in one message.
  5. 🌶️🌶️🌶️level 3
    Challenge 5: Retry until it passesA teammate proposes skipping Task 11's prompt work: run v1, check each attempt with the policy checks and the honesty judge (they need no expect block, so they run on live tickets), and retry up to three times until they pass.
