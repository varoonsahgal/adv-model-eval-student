Concepts

6 ideas, defined where you need them

Each one gets three sentences in the notebook: what it is, what it can't tell you, and an anchor from this lab.

  • 📘
    Side effectA change a tool makes outside the conversation (a booking, a payment, an email) that stays true whatever the agent says next.
  • 📘
    ReducerThe merge rule LangGraph applies when a node returns an update for one state key. The default overwrites; Annotated[list, operator.add] appends.
  • 📘
    Interrupt (human-in-the-loop)A pause the compiled graph takes before a named node. The checkpointer stores the paused state, a person or a policy reads the pending call, and invoke(None, config) resumes.
  • 📘
    End-state gradingCompare what is true after the run (the bookings in WORLD) with what the user asked for (EXPECTED_BOOKINGS), plus evidence that the required lookups happened and that the answer doesn't contradict them.
  • 📘
    InvariantA rule every acceptable trajectory obeys whichever path it takes: a forbidden action (INV-1), a dependency (INV-2), a guard (INV-3), a budget (INV-4).
  • 📘
    Lucky passA run that reaches the right end state while breaking an invariant. Its opposite is inefficiency: the right end state by a wasteful but safe path (extra lookups, a corrected typo).

Words you’ll meet

Jargon decoder

The notebook defines each term right before you need it. Here’s the cheat sheet.

Required action
a tool call that must happen
Forbidden action
a tool call that must not happen
Dependency
an action allowed only after another
Invariant
a rule every acceptable trajectory obeys, whatever its path
End state (the outcome)
what is actually true after the run
Agent
a model in a loop: plan → call a tool → read the result → repeat until it answers
Tool call / tool result
the model's structured request to run a function (name + args), and what the function returned
Trajectory (trace)
the ordered record of a run's tool calls, results and final answer
Side effect
a change that persists outside the conversation (a booking, a payment), whatever the agent says afterwards
End state (outcome)
what is actually true after the run: here, the bookings in WORLD
Invariant
a rule every acceptable run obeys, whichever path it takes
LangChain
a Python library of LLM building blocks: tools, message types, model wrappers, create_agent
All 34 terms in this lab
LangGraph
LangChain's library for running an app as a graph of steps over a shared state
StateGraph
LangGraph's graph builder: declare the state, add nodes and edges, then compile()
State
the one dict every node reads; a TypedDict declares its keys and their types
Node / edge
a node is a function state → update; an edge says which node runs next
Conditional edge
a function that reads the state and returns the name of the next node
Reducer
the merge rule for one state key when a node returns an update: overwrite (default) or, e.g., append
Checkpointer
saves a snapshot of the state after every step, filed under a thread_id; enables replay and pauses
Interrupt
a pause the graph takes before a named node, resumable later: the hook for human approval
@tool
LangChain decorator that turns a Python function into a tool: name, typed argument schema, description
ReAct loop
reason → act (call a tool) → observe the result → repeat; the loop your graph implements
HumanMessage / AIMessage / ToolMessage
LangChain's typed chat messages: what the user said, what the model replied (possibly tool calls), what a tool returned
Precision / recall / F1
share of called tools that were needed / share of needed tools that were called / their harmonic mean
Schema vs semantic validation
"is it well-formed?" (types, formats) vs "does it make sense?" (check-out after check-in)
OTel span
one timed unit of work in an OpenTelemetry trace, with a name and attributes
τ-bench
an agent benchmark (Yao et al., 2024) that grades each run by the final database state
Lucky pass
the right end state reached while breaking an invariant
Canonical call
tool name + arguments serialized as sorted JSON, so equal calls compare equal
create_agent / ToolNode
LangChain 1.x's prebuilt agent loop (a model node and a tools node); the ToolNode runs every tool call the model asked for
Middleware
hooks create_agent runs around model and tool calls (human approval, summarization, …)
Control total
an independent count (of records, steps or money) that a log or batch must reconcile to; a mismatch means entries were lost or added
At-least-once delivery
a sender that retries until it gets an acknowledgement, so the same message (or booking) can arrive twice
Idempotency key
a unique ID sent with a side-effect call so that a retry can't execute it twice

🏆 Challenges

5 problems that need thinking, not typing

Each one is built around a point you discover by solving it. Starters run as shipped; 🌶️ is the spice level.

  1. 🌶️level 1
    Challenge 1: Break the grader with a do-nothing agentA grader that passes an agent doing nothing measures your test data, not your agent, and every number built on it is inflated.
  2. 🌶️🌶️level 2
    Challenge 2: Did the agent pick the option the user asked for?An agent that books the first option instead of the cheapest passes every structural check and overpays on every trip; DEBUG-A overpaid by $102.
  3. 🌶️🌶️🌶️level 3
    Challenge 3: The double chargeOne timeout plus one blind retry and the customer pays twice, while the invariant written to protect their money reports clean.
  4. 🌶️🌶️level 2
    Challenge 4: Approval fatigue, or pause where the money movesA payments agent that asks a human to approve every step trains its reviewers to click "approve" without reading, and by the second week the control exists only on paper.
  5. 🌶️🌶️🌶️level 3
    Challenge 5: Reconcile the log before you grade itA bookkeeping agent's audit trail silently drops entries after a refactor; the loop and ordering checks report clean because the evidence is gone, and month-end close signs off on it.
